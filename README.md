# CRM System

Система управления клиентами и рекламными кампаниями. Приложение позволяет вести каталог услуг, управлять рекламными компаниями, работать с потенциальными и активными клиентами, а также заключать и контролировать контракты.

---

## Роли

Все роли могут видеть статистику по рекламным кампаниям

### Суперадмин (Superuser)

Полный доступ ко всему приложению и панели администрирования.

- Просматривает и редактирует любые данные
- Создаёт, изменяет и удаляет пользователей, роли и разрешения
- Управляет группами и назначает права
- Единственный, кто может деактивировать/удалить другого суперпользователя
- Единственный имеет доступ к admin панели

### Администратор (Administrator)

Управляет пользователями

- Просматривает список пользователей
- Создаёт новых пользователей
- Редактирует профили пользователей
- Назначает роли и права (кроме системных)
- Не может удалять пользователя, только переводит в активный/архив
- **Не имеет** доступа к клиентам, услугам, контрактам и рекламным компаниям

### Оператор (Operator)

Работает с потенциальными клиентами.

- Просматривает список потенциальных клиентов
- Создаёт новых потенциальных клиентов
- Редактирует данные потенциальных клиентов
- **Не имеет** доступа к активным клиентам, услугам, контрактам и рекламным компаниям

### Менеджер (Manager)

Управляет контрактами и активными клиентами.

- Просматривает всех клиентов (потенциальных и активных)
- Переводит потенциальных в активных клиентов
- Не может редактировать данные клиентов
- Создаёт, редактирует и закрывает контракты
- Загружает дополнительные файлы к контрактам
- **Не имеет** доступа к управлению пользователями, услугами и рекламным компаниям

### Маркетолог (Marketer)

Управляет рекламными компаниями и каталогом услуг.

- Создаёт, редактирует и удаляет рекламные компании
- Создаёт и управляет рекламными каналами
- Управляет каталогом услуг (создание, редактирование, удаление)
- **Не имеет** доступа к клиентам, контрактам

## Модели

### Пользователь (User)

Человек, работающий в системе. У каждого пользователя есть имя, фамилия, телефон, роль и история создания (кто создал запись). Суперадмин может назначить пользователю любую роль и набор прав.

### Услуга (Service)

Услуга, которую компания предоставляет клиентам. Услуга имеет название, описание, стоимость и статус (активна/неактивна). Каждая услуга связана с рекламными компаниями и контрактами.

### Рекламная компания (AdCompany)

Рекламная кампания, привлекающая клиентов на конкретную услугу. Компания связана с услугой и может использовать один или несколько рекламных каналов. У компании есть бюджет, статус активности и статистика по привлечённым клиентам.

### Рекламный канал (Channel)

Источник привлечения клиентов (например: соцсети, контекстная реклама, холодные звонки). Канал может использоваться в нескольких рекламных компаниях одновременно.

### Потенциальный клиент (PotentialClient)

Человек, заинтересованный в услуге, но ещё не заключивший контракт. Привязан к рекламной кампании, через которую пришёл. Из потенциального клиента может стать активным — при заключении контракта.

### Активный клиент (ActiveClient)

Клиент, заключивший контракт. Связывает в себе данные потенциального клиента и конкретный контракт. Каждый активный клиент — это всегда один потенциальный клиент и один контракт.

### Контракт (Contract)

Договор между компанией и клиентом на оказание услуги. Содержит даты начала и окончания, стоимость, статус (закрыт/открыт), а также файл договора и дополнительные документы.

### Дополнительные файлы (ExtraFilesToContract)

Дополнительные документы, прикреплённые к контракту (дополнительные соглашения, акты и т.д.).

---

## Связи между моделями

- **Услуга** связана с рекламными компаниями и контрактами — одна услуга может иметь несколько компаний и контрактов.
- **Рекламная компания** привязана к одной услуге и может использовать несколько каналов.
- **Потенциальный клиент** привязан к рекламной кампании, через которую пришёл.
- **Активный клиент** связывает потенциального клиента и контракт — это переход клиента из «потенциального» в «активного».
- **Контракт** привязан к услуге и может содержать дополнительные файлы.

## Запуск

### Через Django (локальная разработка)

1. Создайте виртуальное окружение и установите зависимости:

```bash
python -m venv .venv
source .venv/bin/activate  # Linux/Mac
.venv\Scripts\activate     # Windows

pip install poetry
poetry install
```

2. Скопируйте `.env_template` в `.env` и заполните параметры (секретный ключ, настройки БД).

3. Выполните миграции:

```bash
python manage.py migrate
```

4. Создайте суперадмина (для входа в систему):

```bash
python manage.py createsuperuser
```

Введите имя пользователя, email и пароль. Суперадмин получит полный доступ ко всем функциям.

5. Создайте роли по умолчанию (группы с разрешениями):

```bash
python manage.py create_roles
```

6. Запустите сервер:

```bash
python manage.py runserver
```

Откройте `http://127.0.0.1:8000` в браузере.

### Через Docker

1. Скопируйте `.env_template` в `.env` и заполните параметры. Убедитесь, что `host=db` (не `localhost`).

2. Запустите контейнеры:

```bash
docker compose up --build -d
```

При первом запуске автоматически:
- Создаётся база данных PostgreSQL
- Выполняются все миграции
- Создаётся суперадмин (логин: из `.env`, пароль: из `.env`)
- Создаются роли по умолчанию

3. Откройте `http://localhost:8000` в браузере.

Для остановки:

```bash
docker compose down
```

Для полного сброса данных:

```bash
docker compose down -v
```
